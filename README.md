给 DeepSeek Harness 的界面**按类别上色**：思考、命令（**按危险性分三级**）、读写文件、搜索、网络请求、其他工具。另外还能给输入框附近的**界面控件**（权限选择、计划模式）单独配色，权限选择会**按当前等级自动换色**。

内置三套预设色板 —— **中国传统色（默认）**、**日本传统色**、**马卡龙色系** —— 也可以逐个类别自定义颜色，浅色与深色主题分别设置。

---

## 它做什么

| 类别 | 着色对象 |
|---|---|
| 思考 / 推理 | 推理行、过程组标题（"正在分析请求"） |
| 命令 · **低/中/高**风险 | `bash` / `pwsh` 工具行与过程组标题，按命令文本的风险词表分三级 |
| 读取文件 | `read` / `read_image` |
| 写入 / 编辑 | `write` / `edit` / `run_code` |
| 搜索 | `grep` / `glob`（本地搜索） |
| 网络请求 | `web_search` / `web_fetch` |
| 重试模型请求 | 模型重试行（`_retryRow`） |
| 其他工具 | 未分类的工具 |

界面控件：**权限选择**（按等级自动换色）、**计划模式**。

⚠️ 权限选择是**等级切换后实时换色**的 —— 同一个控件的文字会在
「仅可查看 / 工作区内修改 / 完全权限 / Auto review」之间变，颜色跟着变。

**命令的三级风险**用的是一张**中国传统红色系色表**（196 色），按"越危险的对比度越高"
自动挑色 —— 低风险最浅、高风险最重。判定只看命令文本里的危险迹象
（`rm -rf /`、`mkfs`、`dd of=/dev/`、`DROP TABLE` 为高风险；`sudo`、`curl`、`chmod -R`
为中风险），**不解析 shell**，判错只是颜色不同 —— 本插件不执行、不拦截任何命令。

## 它怎么上色

**只改颜色，不画竖条、不改背景。**

- **图标**：几乎总是上色（`svg` 走 `stroke: currentColor`）；
- **短标签**：只有能确定是短标签时才上色；
- **正文/摘要**：一律不染 —— 可读性优先。

过程组标题（"执行了命令 · 详情"）的处理：内核把「标签 + `' · '` + 详情」
拼成**同一个文本节点**，CSS 没法只染前半段。所以运行时会把标签切出来单独包一层，
**只染标签、详情保持原生** —— 两个诉求（"标签要有颜色"与"正文别被染色"）同时满足。

界面控件（权限选择、计划模式）是**图标与文字一起染**。

展开后的命令输出、diff、文件内容**不会被染色** —— 颜色只作用于折叠表头，
正文保持宿主原生配色。这是刻意的：给大段正文上色会严重伤害可读性。

### 配色怎么来的

三套预设的每个色值都是**算出来的**，不是手工挑的：按类别定一个**语义色相**
（思考=紫、读取=蓝、写入=绿…），再从色库里挑那个色相下、对真实宿主底色
（浅色 `#FFFFFF` / 深色 `#151517`）**对比度达标**、且**色调统一**的颜色。

"色调统一"是 2026-10-16 加的：旧版逐类取最高饱和度，结果紫色刺眼、蓝与靛撞色，
用户反馈"颜色搭配丑陋"。现在所有类别共用一个目标饱和度与亮度，**只让色相不同** ——
色相负责区分，色调负责协调。

权限选择的四个等级各有独立色相：仅可查看（绿）、工作区内修改（蓝）、
完全权限（橙）、Auto review（紫）。

## 安装

桌面版（DeepSeek Harness Desktop）：**设置 → 插件 → 添加插件**，填包名 `dsh-colorful-commands`，然后重启应用。

装好后**想一秒钟确认真生效**：复制 [docs/DEMO-PROMPT.md](./docs/DEMO-PROMPT.md) 里的那段 prompt
发一次，它会一次点亮全部配色类别（含命令三档红、混合活动靛蓝、尾部用量/分支）。

Web / CLI profile：

```sh
dsh plugin --profile web add dsh-colorful-commands
```

从源码安装：

```sh
git clone <本仓库>
cd dsh-colorful-commands
dsh plugin --profile desktop add link:.
```

## 在哪里配置

**侧栏「插件」→ 点开「多彩命令」这个组合包 → 配置区就在它的详情页里。**

⚠️ 是**组合包详情页**，不是「设置」页，也不是「内置插件配置」那组（那组只放官方插件）。
本插件注册的是 `plugins.bundle.config`，key = 包名 `dsh-colorful-commands` ——
这是 plugin-manager 内核用于第三方组合包的插槽。

卡片里可以：

- 总开关（关掉立刻恢复原生配色，设置保留）；
- 选预设（中国传统色【默认】/ 日本传统色 / 马卡龙 / 不预设）；
- 逐个类别设色：**取色器**、**色号输入**（`#RGB` / `#RRGGBB`）、**色板快选**；
- 浅色与深色主题**分别**设置；
- 看**实时预览** —— 预览走的是与真实渲染同一套样式生成器，所以预览与生效结果不可能不一致。

改动先留在草稿里，点**保存**才写回。

## 权限

**不需要任何特殊权限。** 本插件：

- 不读写任何文件；
- 不发起任何网络请求；
- 不注册 HTTP 路由；
- 不执行、不拦截、不修改任何命令 —— 「危险命令」只是一个颜色判定，判错也只影响颜色。

Host 侧只做一件事：声明设置 schema。全部着色逻辑都在浏览器侧。

## 已知限制

- 着色依赖 DSH 暴露的稳定 `data-*` 属性（`data-tool` / `data-variant` / `data-kind` / `data-chat-flow-kind` / `data-slot`）。DSH 大版本升级若改动这些属性，需要更新 `src/classify.js`（该文件是唯一映射点，且有测试兜底）。
- 不提供圆角、字体、动画等改动 —— 那些属于 DSH 主题本身，不在本插件范围内。
- 危险命令判定是**关键词匹配**，不是命令解析器；它的目的只是视觉提示。
