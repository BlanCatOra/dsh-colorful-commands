## 它做什么

| 类别 | 着色对象 |
|---|---|
| 思考 / 推理 | 推理行、过程组标题 |
| **命令 · 低 / 中 / 高**风险 | `bash` / `pwsh` 行 —— 按**命令原文**的危险迹象分三级，三级同属红色系、饱和度递增 |
| 读取文件 | `read`、图片读取 |
| 写入 / 编辑 | `write` / `edit` |
| 搜索 | `grep` / `glob` |
| 网页请求 | `web_search` / `web_fetch` |
| 其他工具 | 未分类工具（中性色） |
| 状态 | 「已完成」成功绿、进度圈四档、混合活动标题、尾部「用量 / 分支」 |
| 界面控件 | 权限选择（按等级换色）、计划模式 |

## 预设与自定义

| 预设 | 色库 | |
|---|---|---|
| **中国传统色**（默认） | 742 色 | 从完整传统色库按语义色相挑选，色调统一、低饱和 |
| 日本传统色 | 58 色 | 更清淡的日式配色 |
| 马卡龙 | 34 色 | 粉彩系，最柔和 |

颜色**不是手写色值** —— 按语义色相 + 统一色调 + 对真实宿主背景的对比度自动挑选。

**每个类别都能单独改**：浅色主题与深色主题**分别设置**，色板快选或直接填 hex，
一键恢复预设值。设置入口在**插件详情页**（见下方「配置」）。

## 为什么耐看、不容易累眼

- **低饱和优先** —— 全局压低饱和度，不用荧光色、不用高饱和正红正蓝。
- **明暗两套独立配色** —— 浅色主题和深色主题各有一套值，不是同一色值硬套。
- **对比度受约束** —— 每个色值对背景的对比度都在 **3.0–10.5** 之间：
  太低看不清，太高刺眼。这条约束写进了测试，改配色会被自动检查。
- **只染该染的** —— 只上色图标、短标签与关键状态；正文与推理内容保持原生色。
  避免整屏彩色带来的视觉噪音，这也是"看久了不累"的关键。
- **觉得哪个刺眼就自己调** —— 任一类别的浅/深色都能改成更淡的值。

**桌面版**：设置 → 插件 → 添加插件，填 `dsh-colorful-commands`，重启应用。


## 命令三档红

按**命令原文**（从 React fiber 读取，不是模型给的描述）匹配危险词：

| 档位 | 触发示例 | 浅色 |
|---|---|---|
| 低 | 普通命令 | `#A7535A` |
| 中 | 含 `sudo`、`curl`、`chmod -R`、`systemctl` 等 | `#C02C38` |
| 高 | 含 `rm -rf /`、`mkfs`、`dd of=/dev/`、`git push --force` 等 | `#DE2A18` |

三档**同属红色系**，只靠饱和度递增表达危险度。

## 已知限制

- 只给**客户端 UI** 上色，不改变任何功能与行为。
- 依赖内核 CSS Module 类名的**稳定后缀**（如 `[class*="_title"]`）；内核若改后缀会失效
  （前缀哈希每次构建都变，所以只匹配后缀）。
- **过程组内层行**（如「创建子智能体」「更新任务清单」）只有**图标**上色，文字保持原生色 ——
  内核没给这些行可区分的语义钩子，见 [AGENTS.md](AGENTS.md) §5.6。
- `japanese` / `macaron` 色库较小，有少量类别的浅色与深色相同（已知缺陷，清单已冻结在测试里）。
